metasmith benchmark · objective 1 · E1 vs E2 on CAMI II

Does metasmith reproduce nf-core/mag?

E1 ran nf-core/mag 5.5.0 on 249 CAMI II samples: 208 short-read and 41 nanopore. E2 ran the same pipeline as a plan metasmith solved from a library of the same tool calls. The three tests below are the workflow each one ran, how it executed, and the genomes it produced.

1 · workflow

The solved plan is nf-core's pipeline, step for step

Left: nextflow's own DAG of the E1 run, cut to the processes that ran on that arm. Right: the plan metasmith solved for E2, the one that ran. Both are drawn by metasmith's DAG renderer, with one colour per pipeline stage.

Tool-level dependenciesboth graphs contracted to the steps that run a tool
The edges only nf-core draws
  • Grey steps are nf-core's bookkeeping and report processes: decompression, renaming, seqkit, FASTA splitting, depth summaries, Prodigal, QUAST and NanoPlot. metasmith does the format conversions inside each transform and runs no report steps.
  • Pink steps are E2's scoring against the CAMI gold standard, which nf-core does not ship.
  • Three transforms each hold two nf-core processes: bowtie2_binning_bam is BUILD and ALIGN, minimap2_binning_bam is INDEX and ALIGN, and metabat2 is the depth table and MetaBAT2.
  • nf-core runs one CheckM2 process over all four bin sets. The plan has one CheckM2 step per bin set.
  • nextflow draws a channel from the trimmed reads straight to each binner and DAS Tool. The plan reaches them through the assembly and the read mapping, so the order of work is the same.

3 · results

The same genomes, within nf-core's own run-to-run noise on short reads

A bin is matched when it has a reciprocal partner in the other run: skani ANI ≥ 95 and aligned fraction ≥ 50% in both directions. The control is a second nf-core run on 25 of the samples over E1's own assemblies, with a new MetaBAT2 and SemiBin2 seed. It measures how much nf-core disagrees with itself.
