# 2a draft: types of use (accepted by Tony, 2026-11-24)

Key message: types join tools, so they must describe how data can be used, where earlier type systems describe format, content or structure.
Points: chaining rule; prior systems (format, content, structure; SADI closest in approach); reads-before-assembly case; KBase records the properties as fields but apps match by type name (verified on the live Workspace: KBaseFile.PairedEndLibrary-2.1 vs SingleEndLibrary-2.1; sequencing_tech, single_genome as fields; app inputs by valid_ws_types); Metasmith property sets.
Ref added: Arkin 2018, Nat Biotechnol 36(7):566-569, doi 10.1038/nbt.4163.

Accepted draft:

Types are what join tools: if the output type of one tool satisfies the input type of another, the two can be chained. A type must therefore describe how data can be used, and this is where Metasmith departs from earlier type systems, which describe the format, content or structure of data. Galaxy assigns every dataset a format class, with sniffers to detect it and converters between formats, and CWL lets a file declare an EDAM format and its secondary files. EDAM's data concepts describe content, and bio.tools uses them to annotate what each tool consumes and produces (Ison 2013; Ison 2016); BioMoby's object ontology did the same for web services (BioMoby Consortium 2008; Kawas 2006). WDL and Nextflow type the structure of values, and Snakemake matches files by name. SADI came closest in approach, describing service inputs and outputs as OWL classes defined by the properties the data carry (Wilkinson 2011), but those properties still record what the data are, not what they are ready for. Whether a set of sequencing reads can go to a given assembler, for example, depends on the platform that produced them, whether they are paired, and which steps such as trimming or host removal have already been applied, and neither a format nor a content class records these. KBase goes furthest, with versioned schemas that record a read library's pairing, sequencing technology and whether it came from a single genome, yet its apps accept data by type name alone, so these properties describe the data without deciding which tool may use it (Arkin 2018). Metasmith's types are sets of properties chosen to capture this fitness for use. Because each tool's contract is written against these types once, a tool becomes chainable with every tool whose types it satisfies.
