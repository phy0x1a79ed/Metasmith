# 2b draft: shared ontology (accepted by Tony, 2026-11-25)

Points: interoperability needs a community standard; Metasmith has none; EDAM lacks state (verified via OLS: operation_3192 Sequence trimming, no trimmed-reads data concept), Lamprecht 2021; BioMoby/SADI hosted online decayed (Zhao 2012); a new standard is counterproductive; local namespaces; narrowed claim plus principle.

Accepted draft:

Interoperability hinges on a shared vocabulary, which requires a standard adopted by a community. Metasmith, as a new tool, has neither. Existing standards fall short in two ways. EDAM, which bio.tools and CWL use to annotate tools and files, describes what data are and which operations act on them, but not the state the data have reached. A planner without this state can produce plans that run but are wrong {Lamprecht, 2021 #88}. BioMoby kept its object ontology in a central registry, and workflows built on it decayed as the registry and its services disappeared {Zhao, 2012 #6}. A new standard from Metasmith would be counterproductive, since many competing standards amount to no standard at all. Metasmith therefore adopts local namespaces that serve specific cases and are to be expanded and joined as they are adopted. Such namespaces, being local, cannot decay with a remote server. Metasmith does not prescribe the vocabulary, just as it does not prescribe the rest of the stack, and its claim is narrower in the absence of a standard. The claim is that the type system is expressive enough to capture use cases such as those in the Results. Metasmith offers less a vocabulary than a principle for building one, which is that a type should draw exactly the distinctions that decide which tools can take the data. The question of which vocabulary becomes standard is left to use. Tools described as typed contracts, rather than the vocabulary that emerges, drive interoperability.
