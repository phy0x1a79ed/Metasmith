# 2b draft: shared ontology (accepted by Tony, 2026-11-25)

Points: interoperability needs a community standard; Metasmith has none; EDAM lacks state (verified via OLS: operation_3192 Sequence trimming, no trimmed-reads data concept), Lamprecht 2021; BioMoby/SADI hosted online decayed (Zhao 2012); a new standard is counterproductive; local namespaces; narrowed claim plus principle.

Accepted draft:

Interoperability hinges on a shared vocabulary, and a shared vocabulary requires a standard adopted by a community; as a new tool, Metasmith has neither. Existing standards fall short in two ways. EDAM describes what data are and which operations act on them, but not the state the data have reached, and without that state a planner can produce plans that run but are wrong (Lamprecht 2021). The shared vocabularies of BioMoby and SADI were hosted online, in a central registry and at each provider respectively, and workflows built on them decayed as those servers disappeared (Zhao 2012). Introducing a new standard of our own would be counterproductive, since where many standards compete, there is in effect no standard. We therefore adopted local namespaces that serve specific cases, to be expanded and joined as they are adopted; being local, they cannot decay with a remote server. Users own the vocabulary as they own the rest of the stack, so our claim is narrower: the type system is expressive enough to capture use cases such as those in the Results. What we offer is less a vocabulary than a principle for building one, namely that a type should draw exactly the distinctions that decide which tools can take the data. Which vocabulary becomes standard is left to use.
