Current draft:

LLM agents offer a third route: generating a pipeline directly from a request. Generated from scratch, however, every step is a fresh guess, and errors compound with each step added. Accuracy on composed tasks falls quickly as the number of steps grows (Dziri 2023), and LLMs cannot reliably verify their own plans (Kambhampati 2024); at 95% per step, a twenty-step pipeline would be fully correct only about a third of the time. On BixBench, 53 analysis scenarios drawn from real bioinformatics studies, frontier agents answered about a fifth of the open questions correctly (Mitchener 2025), and Galaxy and Nextflow workflows generated by LLMs, scored against Galaxy Training Network and nf-core baselines, still needed manual correction before they ran (Alam 2025) [check]. One remedy is to restrict the agent to a curated catalogue of tools, so that it can no longer invent tools or options. Biomni, for example, retrieves from 150 tools, 105 software packages and 59 databases (Huang 2025). A catalogue fixes what can be called, but not how calls connect: tools are still joined by similarity rather than by fit, nothing checks that one step's output is a valid input to the next, and a wrong join, such as predicted genes passed to a binner, runs and returns plausible output. Typed contracts close this remaining gap. A formal planner accepts a join only when an output type satisfies an input type, returns the same plan for the same request, and leaves a reason for every join that a reviewer can check. A better model raises the odds that a join is right, but only types make a join checkable. Agents and planners are therefore complementary rather than competing (Kambhampati 2024): the agent turns a question into a target and chooses among valid plans, while the planner keeps every join proven.
