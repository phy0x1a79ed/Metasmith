# 1b draft: planning (in d2 2026-11-25, pending Tony's review)

If the route were derived rather than written, every module would be reusable at no extra cost to its developer, and this is what automated planning promises. A planner accepts a join only when the output type of one tool satisfies the input type of the next, so every plan it returns is valid by construction; its search is systematic, the same request returns the same plan, and every join carries a reason that a reviewer can check. APE showed that such planning can compose bioinformatics workflows from annotated tools (Kasalica 2020). Earlier planners could not reach their full potential, however, and two things held them back. The first was their types. Types that describe what data are let invalid plans through as candidates, and where the vocabulary was fixed, people had to supply the structure instead: Wings, for example, specialises templates written by experts rather than composing new workflows (Gil 2011). The second was execution, since a plan had no clear path to a protocol that a machine could execute. LLM agents remove this second obstacle, because they can compose and run tools directly, in Nextflow or in a shell, but they do so without the guarantees that planning provides.
