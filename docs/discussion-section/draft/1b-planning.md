If the route were derived rather than written, every module would be reusable at no extra cost to its developer, aligning the incentive of the individual, a faster route to a running pipeline, with that of the community, reuse and reproducibility; this is what automated planning promises. A planner accepts a join only when the output type of one tool satisfies the input type of the next, so every plan it returns is valid by construction; its search is systematic, the same request returns the same plan, and every join carries a reason that a reviewer can check. APE showed that such planning can compose bioinformatics workflows from annotated tools (82). Earlier planners could not reach their full potential, however, and two things held them back. The first was their types. Types that describe what data are let invalid plans through as candidates, and where the vocabulary was fixed, people had to supply the structure instead: Wings, for example, specialises templates written by experts rather than composing new workflows (83). The second was execution, since a plan had no clear path to a protocol that a machine could execute. Metasmith removes both obstacles: its types carry the state that decides which tools can take the data, so invalid joins never become candidates, and every plan compiles to Nextflow, so it runs as written. Planning also acts before execution, which limits the cases a plan can cover. Metasmith already finds strong plans, which remain valid under every outcome in the output sets that contracts declare (84), but conditional planning, which branches on data observed at run time (85), and strong cyclic planning, which allows loops such as refining a product until it meets a threshold (84), have yet to be implemented. LLM agents have been applied as an alternative to planners, one that can also execute: they compose and run tools directly, in Nextflow or in a shell, but without the guarantees that planning provides.
