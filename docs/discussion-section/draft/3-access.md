Galaxy check (2026-11-25): BYOC experimental on usegalaxy.eu only, credentials via staff (pulsar-network.readthedocs.io/en/latest/rabbitmq.html); BYOS self-service from admin templates (galaxyproject.org/news/2024-09-20-esg-byos-im); single-user local install needs no sysadmin; Tool Shed installs are admin-only; 25.0 User-Defined Tools (Beta) for selected users.

Beyond routing, typed contracts are accessible at different levels of expertise, from stating intent to supplying compute. Metasmith's interfaces form a hierarchy of levels, each catering to an audience that spends a different amount of expressiveness to buy accessibility. These levels follow the path from intent to execution. Biologists choose data and a target from templates in the GUI, bioinformaticians shape requests and plans through the notebook, API or command line, and tool developers write the contracts and types on which execution rests. Since each level builds on the one below, a contract written once is available at every level above it. Loach et al. {Loach, 2026 #93} describe flexibility and support as a trade-off on which Galaxy and Nextflow each fix a point, whereas Metasmith lets the user choose where to stand. Since execution is deferred to Nextflow, plans gain its portability and extensibility to new platforms, running on local machines, HPC schedulers, cloud batch services and Kubernetes, with containers or conda environments. This means users own the full stack down to the hardware. In contrast, modifying the system or reaching the compute layer on a public Galaxy server goes through a central authority, and the alternative is to stand up the full server oneself, which is much harder than running a user-facing execution framework like Nextflow. The levels are not yet complete. Adding a new tool still takes expertise that the GUI does not support, only local and Slurm execution were tested here, and accessibility has not been measured in a user study. Owning the stack down to the hardware also means that users could offer it to others, which matters since some compute is too specialized to hand over. Sharing an analysis today means shipping the whole factory, including the tools, environments, references and expertise needed to run it, when the owner may only want to supply the product. In a decentralized compute market, providers could offer their compute as typed contracts and run it themselves, and the planner could place each step on whichever offer fits. Offers could carry track records such as runtime, cost and benchmark scores, and paying providers to keep their offers alive would address the decay that ended earlier service registries. In each case, the typed contract is the common unit. It joins tools, lets a solver choose the route between them, and could let providers offer their compute.
